# 知見の記録

各プロジェクトで得た知見と失敗を、ここに 1 件ずつ記録する。記録してから、どこに入れるかを決める（考え方は [`design.md`](design.md) 6 章）。
`CLAUDE.md` に 1 行足したくなったら、その前にまずここに書く。

## 流れ

1. **プロジェクトで書き留める**。エージェントか人が、プロジェクトの `docs/harness-feedback.md` に 1 件追記する（`common/CLAUDE.md`「ハーネスへのフィードバック」）
2. **ここへ移す**。このリポジトリに、下の書式で 1 件足す。この時点では記録するだけでよい
3. **行き先を決めて反映する**。効きの強い順に検討し、決めた先を直す。記録の「行き先」と「反映」を埋める
   1. スケルトンの構造で、間違えようがなくする
   2. lint やフックで機械的に止める（ガードの穴なら、直す前に `tests/cases/` に 1 行足す）
   3. `CLAUDE.md` に 1 行足す
   4. 人間用のチェックリストに足す
4. **確かめる**。同じことが別のプロジェクトでも起きたら「根拠」に足す。反映したのに効かなかった、一度も引っかからなかった、と分かったら削り、その旨を記録に残す

## 書式

```markdown
### YYYY-MM-DD 何が起きたかを一言で

- **出どころ**：プロジェクト名とタイプ。PR や議論があればリンク
- **何が起きたか**：事実だけ。エージェントが何をして、何がまずかったか
- **なぜ起きたか**：分かる範囲で
- **層**：基底 / タイプ（どれか） / タイプ間の関係
- **行き先**：構造 / フック・lint / CLAUDE.md / チェックリスト / 見送り（理由）
- **根拠**：1 件（仮説） / 2 件以上（どのプロジェクトか）
- **反映**：未 / 済（PR へのリンク）
```

## 決まり

- **事実を書く**。評価や一般論を足さない。「気をつける」で終わる記録は行き先が決まっていない
- **1 件だけの知見は仮説**。反映してよいが、根拠が 1 件であることを残し、2 件目で確かめる
- **プロジェクト固有のものは入れない**。そのプロジェクトの `CLAUDE.md`「プロジェクト固有」に書く。ここに入れるのは、次のプロジェクトにも効くものだけ
- **層は「それが真である一番上」** にする。原則は基底に、置き場所の名指しはタイプに分ける
- 新しいものを上に足す
