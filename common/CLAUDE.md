# 共通ハーネス（全パターン共通・A 層）

このファイルは全プロジェクト共通。各パターンの CLAUDE.md はこの前提で差分だけを書く。

## 作業の進め方

1. **読む**：着手前に関係するファイルと既存のテストを読む。推測で書かない
2. **計画**：3 ファイル以上を触る変更、または設計判断を含む変更は、先に計画を短く示してから着手する
3. **小さく変える**：1 つの変更は 1 つの目的。無関係なリファクタを混ぜない
4. **検証**：変更のたびにそのパターンの `check` コマンドを回す。完了条件は下記
5. **報告**：何を変えたか・何を確認したか・残っている懸念を簡潔に

## 完了の定義

以下が **すべて** 機械的に通って初めて「完了」。1 つでも落ちていれば完了ではない。

- フォーマッタで差分が出ない
- lint が警告ゼロ
- 型チェック / コンパイルが通る
- 既存テストが全て通り、変更に対するテストが追加されている
- 生成コード（OpenAPI, sqlc 等）が最新のスキーマと一致している

テストを通すために既存テストを削除・緩和してはならない。テストが間違っていると判断した場合は理由を示して確認を取る。

## 確認を取るべき判断

次の場合は作業を止めて確認する。

- DB スキーマの変更（カラム削除・型変更・制約変更）
- 公開 API（OpenAPI）の後方互換を壊す変更
- 新しい依存ライブラリの追加
- アーキテクチャの層構造を変える変更（新しい層の追加、依存方向の変更）
- 本番環境・課金・認証まわりに触れる変更
- 既存テストの削除や期待値の変更

## 禁止事項（フックでもブロックしている）

- `git push --force` / `--force-with-lease`、`git reset --hard`、`git clean -f`
- `rm -rf` でプロジェクト外・リポジトリルートを消す操作
- `cdk deploy` / `terraform apply` / `flutter build appbundle --release` 等の本番向け成果物生成・デプロイ
- DB マイグレーションの **適用**（生成は可）
- 署名・notarization・ストア申請・パッケージ公開
- `.env*`、秘密鍵、トークンをファイルに書く・ログに出す・チャットに貼る
- 生成コード（`generated/` 配下）を手で編集する

## Git 運用

- ブランチ：`feat/<短い説明>`、`fix/<短い説明>`、`chore/<短い説明>`
- コミットは Conventional Commits（`feat:`, `fix:`, `refactor:`, `test:`, `docs:`, `chore:`）。1 行目 50 文字以内、本文は「なぜ」を書く
- `main` に直接コミットしない。PR の説明には「変更内容」「確認方法」「スクリーンショット（UI 変更時）」を書く
- コミット前に `check` が通っていること

## コードの書き方（言語横断）

- 既存コードの流儀に合わせる。新しい書き方を持ち込まない
- コメントは「なぜ」だけ。「何を」はコードで表現する
- エラーは握りつぶさない。ログして無視、は禁止
- 早期 return、浅いネスト
- マジックナンバー・文字列を定数に
- 1 関数 1 責務。長くなったら分ける

## 禁止パターン（言語横断）

- 「とりあえず動く」ための一時コード、`TODO` の放置
- 広すぎる例外キャッチ
- テストのスキップ（`skip`, `xit`, `[Ignore]` 等）
- 設定値のハードコード（環境変数 / 設定ファイル経由にする）

## 困ったとき

- 3 回試して通らないものは原因の仮説を書いて止まる。試行錯誤を続けない
- 依存関係のバージョン問題はロックファイルを見てから判断する
- 環境依存で再現しない場合はその旨を報告する
